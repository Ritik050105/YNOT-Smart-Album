YNOT Album Studio - macOS build and acceptance checks

Status: Windows build tested. macOS platform code added, but a Mac build and
real Mac acceptance testing are still required before delivering to clients.
The Windows EXE cannot be installed on macOS.

Build on a Mac with Node.js installed, from this repository:
  npm ci
  npm run build
  npx electron-builder --mac --arm64   (Apple Silicon Mac)
  npx electron-builder --mac --x64     (Intel Mac)
Use a matching-architecture build machine for native dependencies.
The existing macOS configuration supports separate Intel and Apple Silicon DMGs.
For client distribution, configure an Apple Developer ID signing identity and
notarization in the macOS build environment. Do not put credentials in this repo.
See https://www.electronjs.org/docs/latest/tutorial/code-signing for the signing workflow.

Acceptance checks on each supported Mac architecture:
- Launch the packaged app and copy its device ID. Generate its signed license
  using the owner-only admin tool; import it and relaunch.
- Reject a license issued for another machine. Never ship the private signing key.
- Import photos, select and drag a photo into an empty spread; Undo and Redo.
- Resize a photo near a reference width/height: blue outlines and yellow size
  markers appear, the size snaps, and dragging farther releases the snap.
- Empty spreads have no automatic print or empty-frame outlines.
- Check equal-spacing guides, trackpad navigation, Command shortcuts, text input,
  local fonts, save/reopen, PDF/image export, Retina scaling and window resizing.
- If installed, test Photoshop/Canva app discovery and file handoff. This change
  does not add automatic Canva import or cloud save-back.
- Verify Dock/Finder icons, quit/reopen behavior, and signed/notarized installation.

Windows PC IDs are unchanged, so existing valid Windows licenses remain valid.
Owner-only License Admin (Windows and macOS):
  npm run dist:admin
Run on a Mac to produce a DMG for that Mac's architecture (Intel x64 or Apple
Silicon arm64). Run on Windows to produce the portable Windows EXE. Outputs
are in admin-license/release. Build separately on each target architecture.
The application uses the same signed-license format on both platforms. Detect
this computer reads the Mac hardware UUID or Windows hardware identity.
The admin DMG must be signed and notarized for client distribution too.

On the owner Mac, install the admin app in Applications. Choose signing key
and select the existing owner-only signing-private.pem (never generate a new
key for this deployment). Restore the license backup through the app, rather
than copying raw history JSON: restore rewrites file paths for the local OS.
Verify Detect this computer agrees with Album Studio on the same Mac, issue
and activate a test license, test duplicate rejection, backup/restore preview,
Finder reveal, and Command+C/V in the PC ID field. A Mac admin can issue a
license for either platform by pasting the employee computer's ID.

Keep the admin app, signing key and license backup with the studio owner only.
The current USB contains Windows executables; it is NOT a finished Mac kit.
A real Mac build, signing/notarization and acceptance run are still required.

For the USB build launcher and full owner migration flow, use MAC-USB-SETUP.txt.
